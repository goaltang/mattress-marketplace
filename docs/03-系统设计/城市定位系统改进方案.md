# 城市定位系统改进方案

## 1. 现状概述

当前 Restored 的城市定位系统由以下几部分组成：

- **城市数据源**：`src/config/cities.ts` 硬编码 20 个热门城市 + 约 60 个三四线城市。
- **服务端 IP 定位**：`src/app/api/locate/route.ts` 使用 `ip-api.com` 与 `ipinfo.io` 双源 IP 反地理编码。
- **全局状态管理**：`src/context/AppContext.tsx` 负责城市状态、localStorage + Cookie 双写持久化、定位推荐气泡、路由同步。
- **城市选择 UI**：`src/components/CityChooseModal.tsx` 提供自动定位、搜索框、热门城市快选。
- **首页中间件**：`src/middleware.ts` 根据 `city_slug` Cookie 将 `/` 重定向到 `/{city_slug}`。
- **城市路由**：`src/app/[city]/page.tsx` 动态路由承载各城市首页。

当前方案已能支撑 MVP 阶段，但在定位精度、国内可用性、代码一致性、用户体验上仍有提升空间。

## 2. 改进目标

1. **提升定位精度**：优先使用浏览器 H5 地理定位，IP 定位作为兜底。
2. **增强国内可用性**：引入国内 IP 定位服务作为备用，降低国际服务不稳定的影响。
3. **统一城市标识**：全局统一使用 lowercase `slug`，消除 `currentCity` 大小写混用问题。
4. **扩展城市覆盖**：提供可维护的城市数据扩展机制，减少硬编码维护成本。
5. **细化定位失败处理**：区分“权限拒绝”“定位超时”“城市未覆盖”“网络错误”等场景，给出对应提示与降级策略。
6. **保持非强制跳转体验**：首次访问仍以气泡推荐为主，不强制跳转。

## 3. 改进方案总览

```
│                    客户端定位触发方式                         │
```

## 4. 详细实现

### 4.1 统一城市标识：全局使用 lowercase slug

#### 问题

当前 `AppContext` 中 `currentCity` 默认值为 `"Beijing"`，但路由、Cookie、API 都使用 lowercase slug。代码里出现大量 `.toLowerCase()` 转换，容易出错。

#### 改造方案

- `currentCity` 改为始终存储 lowercase slug，如 `"beijing"`。
- 显示时通过 `getCityName(slug)` 获取中文名，不需要维护两套状态。
- Header 等组件直接接收 slug，由 `getCityName` 解析中文。

#### 涉及修改

### 4.2 新增 H5 地理定位 Hook

浏览器 H5 定位精度远高于 IP 定位，建议在城市选择器中优先尝试。由于需要用户授权，应由用户主动触发（点击“自动定位”），避免首次静默弹窗授权。

#### 新建 `src/hooks/useGeolocation.ts`

```ts
"use client";

import { useState, useCallback } from "react";

export type GeolocationErrorCode =
  | "PERMISSION_DENIED"
  | "POSITION_UNAVAILABLE"
  | "TIMEOUT"
  | "NOT_SUPPORTED";

interface GeolocationResult {
  latitude: number;
  longitude: number;
  accuracy: number;
}

interface UseGeolocationReturn {
  isLoading: boolean;
  error: GeolocationErrorCode | null;
  locate: () => Promise<GeolocationResult | null>;
}

export function useGeolocation(timeoutMs = 10000): UseGeolocationReturn {
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<GeolocationErrorCode | null>(null);

  const locate = useCallback(async (): Promise<GeolocationResult | null> => {
    if (typeof navigator === "undefined" || !navigator.geolocation) {
      setError("NOT_SUPPORTED");
      return null;
    }

    setIsLoading(true);
    setError(null);

    return new Promise((resolve) => {
      navigator.geolocation.getCurrentPosition(
        (position) => {
          setIsLoading(false);
          resolve({
            latitude: position.coords.latitude,
            longitude: position.coords.longitude,
            accuracy: position.coords.accuracy,
          });
        },
        (err) => {
          setIsLoading(false);
          const codeMap: Record<number, GeolocationErrorCode> = {
            1: "PERMISSION_DENIED",
            2: "POSITION_UNAVAILABLE",
            3: "TIMEOUT",
          };
          const mapped = codeMap[err.code] || "POSITION_UNAVAILABLE";
          setError(mapped);
          resolve(null);
        },
        {
          enableHighAccuracy: false,
          timeout: timeoutMs,
          maximumAge: 5 * 60 * 1000, // 5 分钟内缓存可用
        }
      );
    });
  }, [timeoutMs]);

  return { isLoading, error, locate };
}
```

### 4.3 改造 `/api/locate`：支持 H5 坐标逆地理编码 + 多源 IP

#### 改造目标

- 接收 `source` 参数：`h5` | `ip` | `auto`。
- `h5` 模式：接收经纬度，调用逆地理编码服务解析城市。
- `ip` 模式：按优先级调用定位服务：
  1. 国内 IP 定位（推荐高德 IP 定位，需申请 Key）
  2. `ip-api.com`
  3. `ipinfo.io`
- `auto` 模式：服务端只做 IP 定位，供首次静默调用。
- 返回统一结构：
  ```json
  {
    "success": true,
    "slug": "hangzhou",
    "name": "杭州",
    "source": "h5",
    "confidence": "high"
  }
  ```

#### 环境变量配置

```bash
# .env.local
GAODE_IP_KEY=your_gaode_key
GAODE_REGEO_KEY=your_gaode_key  # 可与 IP Key 相同
```

#### 逆地理编码工具

```ts
// src/utils/geo.ts
import { ALL_CITIES } from "@/config/cities";

export function resolveCitySlug(rawCity: string): string | null {
  if (!rawCity) return null;
  const cleaned = rawCity.replace(/市$/, "").trim();
  const exact = ALL_CITIES.find((c) => c.name === cleaned);
  if (exact) return exact.slug;
  const contains = ALL_CITIES.find(
    (c) => cleaned.includes(c.name) || c.name.includes(cleaned)
  );
  if (contains) return contains.slug;
  const lower = cleaned.toLowerCase();
  const bySlugOrPinyin = ALL_CITIES.find(
    (c) => c.slug === lower || c.pinyin === lower || lower.startsWith(c.pinyin)
  );
  if (bySlugOrPinyin) return bySlugOrPinyin.slug;
  return null;
}

export function normalizeCityName(raw: string): string {
  if (!raw) return "";
  const slug = resolveCitySlug(raw);
  if (slug) {
    const city = ALL_CITIES.find((c) => c.slug === slug);
    return city?.name || raw;
  }
  return raw.replace(/市$/, "").trim();
}
```

```ts
// src/utils/geo/gaode.ts
interface GaodeRegeoResult {
  status: string;
  regeocode?: {
    addressComponent: {
      city: string | string[];
      province: string;
      district: string;
    };
  };
}

export async function gaodeReverseGeocode(
  lat: number,
  lng: number,
  key: string
): Promise<{ city: string; province: string } | null> {
  try {
    const url = `https://restapi.amap.com/v3/geocode/regeo?key=${key}&location=${lng},${lat}&extensions=base`;
    const res = await fetch(url, { signal: AbortSignal.timeout(5000) });
    const data: GaodeRegeoResult = await res.json();
    if (data.status === "1" && data.regeocode) {
      const city = data.regeocode.addressComponent.city;
      return {
        city: Array.isArray(city) ? city[0] || "" : city,
        province: data.regeocode.addressComponent.province,
      };
    }
  } catch {}
  return null;
}

interface GaodeIpResult {
  status: string;
  info?: string;
  province?: string;
  city?: string;
}

export async function gaodeIpLocate(
  ip: string | null,
  key: string
): Promise<{ city: string; province: string } | null> {
  try {
    const url = ip
      ? `https://restapi.amap.com/v3/ip?key=${key}&ip=${ip}`
      : `https://restapi.amap.com/v3/ip?key=${key}`;
    const res = await fetch(url, { signal: AbortSignal.timeout(5000) });
    const data: GaodeIpResult = await res.json();
    if (data.status === "1" && data.city) {
      return { city: data.city, province: data.province || "" };
    }
  } catch {}
  return null;
}
```

#### 改造后的 `/api/locate/route.ts`

```ts
import { NextResponse, type NextRequest } from "next/server";
import { ALL_CITIES } from "@/config/cities";
import { resolveCitySlug, normalizeCityName } from "@/utils/geo";
import { gaodeIpLocate, gaodeReverseGeocode } from "@/utils/geo/gaode";

const TIMEOUT_MS = 5000;

interface LocateResult {
  success: boolean;
  slug: string;
  name: string;
  source: "h5" | "ip" | "none";
  confidence: "high" | "medium" | "low";
  reason?: string;
}

function getClientIp(request: NextRequest): string | null {
  let ip = request.headers.get("x-forwarded-for") || request.headers.get("x-real-ip");
  if (ip && ip.includes(",")) {
    ip = ip.split(",")[0].trim();
  }
  if (ip && ip.startsWith("::ffff:")) {
    ip = ip.slice(7);
  }
  if (!ip || ip === "::1" || ip === "127.0.0.1" || ip === "localhost") {
    return null;
  }
  return ip;
}

async function tryIpApi(ip: string | null): Promise<{ city: string; province: string } | null> {
  try {
    const url = ip
      ? `http://ip-api.com/json/${encodeURIComponent(ip)}?lang=zh-CN&fields=status,message,city,regionName,query`
      : `http://ip-api.com/json/?lang=zh-CN&fields=status,message,city,regionName,query`;
    const res = await fetch(url, { signal: AbortSignal.timeout(TIMEOUT_MS) });
    const data = await res.json();
    if (data.status === "success" && data.city) {
      return { city: data.city, province: data.regionName || "" };
    }
  } catch {}
  return null;
}

async function tryIpInfo(ip: string | null): Promise<{ city: string; province: string } | null> {
  try {
    const url = ip ? `https://ipinfo.io/${encodeURIComponent(ip)}/json` : `https://ipinfo.io/json`;
    const res = await fetch(url, { signal: AbortSignal.timeout(TIMEOUT_MS) });
    const data = await res.json();
    if (data.city) {
      return { city: data.city, province: data.region || "" };
    }
  } catch {}
  return null;
}

async function ipLocate(ip: string | null): Promise<{ city: string; province: string; source: "ip" } | null> {
  const gaodeKey = process.env.GAODE_IP_KEY;
  const gaodeResult = gaodeKey ? await gaodeIpLocate(ip, gaodeKey) : null;
  if (gaodeResult) return { ...gaodeResult, source: "ip" };

  const ipApiResult = await tryIpApi(ip);
  if (ipApiResult) return { ...ipApiResult, source: "ip" };

  const ipInfoResult = await tryIpInfo(ip);
  if (ipInfoResult) return { ...ipInfoResult, source: "ip" };

  return null;
}

export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url);
  const source = searchParams.get("source") || "auto"; // h5 | ip | auto
  const lat = searchParams.get("lat");
  const lng = searchParams.get("lng");
  const ip = getClientIp(request);

  // H5 模式：使用客户端经纬度
  if (source === "h5" && lat && lng) {
    const latitude = parseFloat(lat);
    const longitude = parseFloat(lng);
    if (!isNaN(latitude) && !isNaN(longitude)) {
      const gaodeKey = process.env.GAODE_REGEO_KEY;
      const raw = gaodeKey ? await gaodeReverseGeocode(latitude, longitude, gaodeKey) : null;
      const cityName = raw ? normalizeCityName(raw.city) : "";
      const slug = cityName ? resolveCitySlug(cityName) : null;

      if (slug) {
        return NextResponse.json({
          success: true,
          slug,
          name: cityName,
          source: "h5",
          confidence: "high",
        });
      }

      // H5 解析失败则降级到 IP 定位
      const fallback = await ipLocate(ip);
      if (fallback) {
        const fallbackName = normalizeCityName(fallback.city);
        const fallbackSlug = resolveCitySlug(fallbackName);
        if (fallbackSlug) {
          return NextResponse.json({
            success: true,
            slug: fallbackSlug,
            name: fallbackName,
            source: "ip",
            confidence: "medium",
            reason: "h5_reverse_geocode_failed",
          });
        }
      }

      return NextResponse.json({
        success: false,
        slug: "",
        name: "",
        source: "none",
        confidence: "low",
        reason: "h5_city_not_supported",
      });
    }
  }

  // IP 模式 / auto 模式
  const result = await ipLocate(ip);
  if (result) {
    const name = normalizeCityName(result.city);
    const slug = resolveCitySlug(name);
    if (slug) {
      return NextResponse.json({
        success: true,
        slug,
        name,
        source: "ip",
        confidence: "medium",
      });
    }
    return NextResponse.json({
      success: false,
      slug: "",
      name: "",
      source: "ip",
      confidence: "low",
      reason: "ip_city_not_supported",
    });
  }

  return NextResponse.json({
    success: false,
    slug: "",
    name: "",
    source: "none",
    confidence: "low",
    reason: "all_locate_methods_failed",
  });
}
```

### 4.4 改造城市选择器：集成 H5 定位 + 细分错误提示

在城市选择弹窗中，点击“自动定位”时，优先使用 H5 定位；如果用户拒绝或不可用，再降级到 IP 定位。

```tsx
    .then((data) => {
      if (data.success && Array.isArray(data.notifications)) {
        setUnreadNotifCount(data.notifications.filter((n: NotificationItem) => n.unread).length);
      }
    })
    .catch(() => {});

  try {
    const storedDismissed = localStorage.getItem("restored_location_prompt_dismissed_v1") === "true";
    setIsPromptDismissed(storedDismissed);
  } catch {}

  try {
    const storedCity = localStorage.getItem("restored_current_city_v1");
    if (storedCity) {
      const slug = storedCity.toLowerCase();
      setCurrentCity(slug);
      document.cookie = `city_slug=${slug}; path=/; max-age=31536000`;
    } else {
      // 首次进入的新用户：后台静默 IP 定位，不做强制跳转
      fetch("/api/locate?source=auto")
        .then((res) => res.json())
        .then((data) => {
          if (data?.success && data.slug) {
            const locatedCityZh = data.name || getCityName(data.slug) || data.slug;
            setSuggestedCity({ slug: data.slug, name: locatedCityZh });
          }
        })
        .catch(() => {});
    }
  } catch {
    setCurrentCity(DEFAULT_CITY_SLUG);
  }
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, []);
```

### 4.6 城市数据扩展机制

将城市按区域/省份分组，便于搜索展示：

```ts
    ],
  },
  // ...

```

#### 长期：从后端 API 获取

增加 `/api/cities` 接口，城市数据存入 Supabase 或其他数据库，支持：

```ts
interface City {
  id: string;
  name: string;
```

客户端启动时缓存到 `localStorage`，减少对配置文件的依赖。

### 4.7 定位失败细分处理总结

| 场景 | 前端提示 | 降级行为 |
|------|---------|---------|
| 用户拒绝 H5 定位 | “浏览器定位权限被拒绝，已为您切换为 IP 定位” | 自动尝试 IP 定位 |
| H5 定位超时 | “定位超时，已为您切换为 IP 定位” | 自动尝试 IP 定位 |
| H5 不支持 | “当前浏览器不支持定位，已为您切换为 IP 定位” | 自动尝试 IP 定位 |
| H5 解析到未覆盖城市 | “当前城市暂未开通服务，请手动选择附近城市” | 保留弹窗，显示热门城市 |
| IP 定位失败 | “定位失败，请手动选择城市” | 保持当前城市，展示搜索框 |
| IP 定位到未覆盖城市 | “当前城市暂未开通服务，请手动选择附近城市” | 保持弹窗，高亮热门城市 |

## 5. 实施优先级建议

| 优先级 | 改进项 | 预估工作量 | 收益 |
|-------|--------|----------|------|
| P0 | 统一 `currentCity` 为 lowercase slug | 1 小时 | 消除大量 `.toLowerCase()`，降低 Bug 风险 |
| P0 | 改造 `/api/locate` 支持 `source` 参数 | 2-3 小时 | 支持 H5 坐标传入，结构更清晰 |
| P1 | 新增 `useGeolocation` Hook 并接入 CityChooseModal | 2 小时 | 提升自动定位精度 |
| P1 | 接入高德 IP 定位（申请 Key 后） | 1-2 小时 | 提升国内 IP 定位稳定性 |
| P2 | 城市数据分组/后端化 | 半天-1 天 | 长期可维护 |
| P2 | 定位失败细分提示 | 1 小时 | 提升用户体验 |

## 6. 风险与注意事项

1. **H5 定位需要 HTTPS**：生产环境必须使用 HTTPS，否则 `navigator.geolocation` 在部分浏览器中不可用。
2. **用户授权体验**：H5 定位会触发浏览器授权弹窗，必须放在用户主动点击“自动定位”后触发，避免首次静默弹窗。
3. **高德 Key 安全**：高德 Key 应放在服务端环境变量中，不要暴露到前端。
4. **隐私合规**：IP 定位和 H5 定位都属于位置信息收集，建议在隐私政策中说明用途。
5. **国内 IP 服务配额**：高德、腾讯、百度的 IP 定位服务都有免费额度，超出后需要付费或限流。

## 7. 总结

本方案在保留当前“非强制跳转 + 推荐气泡”友好体验的基础上，从三个维度提升城市定位系统：

- **精度**：H5 定位优先，IP 兜底。
- **可用性**：增加国内 IP 服务，减少国际服务抖动。
- **体验**：细分错误原因，给出清晰提示；统一 slug 标识，减少代码隐患。

建议按 P0 → P1 → P2 的顺序分阶段实施，优先完成标识统一和 API 接口改造，再逐步接入 H5 和国内 IP 服务。
