# 数据流与降级策略

## 设计原则

平台采用 **Supabase 优先、localStorage 兜底** 的双层架构：
- 有 Supabase 配置时：所有数据走数据库，支持多设备同步
- 无 Supabase 或连接失败时：自动降级到本地存储，核心功能可用

## 各模块数据流

### 1. 城市商品列表（`/[city]`）

```
服务端渲染:
  getListings(city)
    → Supabase 查询?
      → 成功: 返回 DB 数据
      → 失败/超时: 降级到 DEFAULT_LISTINGS

客户端合并:
  CityBrowseClient.useEffect
    → 读取 localStorage "restored_listings_v1"
    → 过滤当前城市 + 与服务端数据去重
    → 合并展示（localStorage 独有项排在前面）
```

**关键点**：服务端不读 localStorage，客户端 useEffect 补齐本地数据。

### 2. 商品详情（`/listing/[id]`）

```
服务端渲染:
  getListingById(id)
    → Supabase 查询?
      → 成功: 返回 DB 数据
      → 失败: 降级到 DEFAULT_LISTINGS 匹配

客户端兜底:
  ListingDetailClient.useEffect
    → 如果 initialListing 为 null
    → 读取 localStorage "restored_listings_v1"
    → 查找 id 匹配项
```

### 3. 发布商品（`/post`）

```
PostListing.handleSubmit
  → 构建 MattressListing 对象（含 sellerDeviceId）
  → onPublish(newListing)
    → 1. localStorage 写入备份（"restored_listings_v1"）
    → 2. Server Action: publishListing(newListing)
         → Supabase INSERT
         → revalidatePath(/city) 清除页面缓存
    → 3. router.push(/city) 跳转城市页
```

**双重写入**：localStorage 保证离线可见，Supabase 保证其他用户可见。

### 4. 收藏功能

```
AppContext.toggleFavorite(id)
  → 乐观更新: setFavorites + localStorage 同步
  → 后台异步: fetch /api/favorites
    → POST (添加) 或 DELETE (取消)
    → 携带 cookie device_id + body device_id

启动同步:
  AppContext 初始化
    → syncFavorites() 从 localStorage 读取
    → syncFavoritesFromDB() 从 Supabase 合并
    → 合并策略: 取并集
```

### 5. 通知系统

```
创建通知（联系卖家）:
  ListingDetail.handleSendContactRequest
    → 读取 listing.sellerDeviceId
    → POST /api/notifications { device_id: sellerDeviceId, ... }

读取通知:
  MessagesView.fetchNotifications
    → GET /api/notifications?device_id=xxx
    → 从 cookie 或 query param 获取 device_id

更新通知（同意/拒绝/降价）:
  MessagesView.handleAcceptRequest 等
    → PATCH /api/notifications
    → 服务端校验 cookie device_id 一致性
```

### 6. 降价功能

```
MessagesView.handlePriceAdjustSubmit
  → 1. 乐观更新: 本地 listings + notifications 状态
  → 2. PATCH /api/notifications（更新通知状态）
  → 3. PATCH /api/listings（更新商品价格）
       → 服务端校验 sellerDeviceId === cookie device_id
```

## 降级矩阵

| 功能 | Supabase 正常 | Supabase 不可用 |
|------|--------------|----------------|
| 浏览商品 | DB 查询 | DEFAULT_LISTINGS + localStorage |
| 发布商品 | DB INSERT + localStorage | 仅 localStorage |
| 商品详情 | DB 查询 | localStorage 查找 |
| 收藏 | DB + localStorage 双写 | 仅 localStorage |
| 通知 | DB CRUD | API 返回 503，前端无数据 |
| 降价 | DB UPDATE | API 返回 503，仅本地状态更新 |
| IP 定位 | 太平洋 API | 默认北京 |

## localStorage 键名规范

| Key | 类型 | 说明 |
|-----|------|------|
| `restored_device_id_v1` | string | 旧版 device_id（已废弃，兼容读取） |
| `restored_favorites_v1` | string[] | 收藏列表 JSON |
| `restored_listings_v1` | MattressListing[] | 用户发布的商品 JSON |
| `restored_current_city_v1` | string | 当前城市名 |

> 注意：`device_id` 的可信来源已从 localStorage 迁移到 HttpOnly Cookie。localStorage 中的值仅在 cookie 缺失时作为 fallback。

## 超时策略

所有 Supabase 查询均设置超时：

| 场景 | 超时时间 |
|------|----------|
| 页面数据加载（getListings / getListingById） | 5s |
| API 路由（notifications / favorites / listings） | 8s |
| IP 定位（太平洋 API） | 5s × 2次重试 |

超时后自动降级，不影响页面渲染。
