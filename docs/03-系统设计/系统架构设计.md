# 系统架构设计

## 架构概览

本项目采用 **Next.js 14 App Router** 架构，结合服务端渲染（SSR）和客户端交互，实现高性能的二手床垫交易平台。

```
┌─────────────────────────────────────────────────────────┐
│                      客户端浏览器                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────┐  │
│  │  React   │  │ Tailwind │  │   LocalStorage       │  │
│  │  组件树   │  │   CSS    │  │   (降级/缓存)        │  │
│  └──────────┘  └──────────┘  └──────────────────────┘  │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│                   Next.js 14 应用层                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────┐  │
│  │Middleware│  │App Router│  │   Server Actions     │  │
│  │(城市路由) │  │ (路由)   │  │   (数据写入)         │  │
│  └──────────┘  └──────────┘  └──────────────────────┘  │
└────────────────────────┬────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐

│  │ Supabase │  │ Supabase │  │   IP 定位 API        │  │
```

## 核心架构模式

### 1. 路由架构

| 路由 | 类型 | 渲染方式 | 说明 |
|------|------|----------|------|
| `/` | 静态 | SSR | 根路由，Middleware 重定向到城市页 |
| `/[city]` | 动态 | SSR + CSR | 城市浏览页，服务端拉取数据 |
| `/listing/[id]` | 动态 | SSR + CSR | 商品详情页 |
| `/post` | 静态 | CSR | 发布商品页 |
| `/me` | 静态 | CSR | 个人中心页 |
| `/api/*` | API | 服务端 | RESTful API 端点 |

### 2. 数据流架构

```
用户操作 → React 组件 → Server Action / API Route → Supabase
                ↓
         LocalStorage (降级/缓存)
                ↓
         AppContext (全局状态)
                ↓
         其他组件 (响应式更新)
```

### 3. 降级策略

系统采用 **三层降级架构** 确保离线可用：

| 层级 | 服务 | 降级目标 |
|------|------|----------|
| 数据库 | Supabase | LocalStorage + 默认数据 |
| 存储 | Supabase Storage | Base64 编码 |
| 定位 | IP 定位 API | 默认城市（北京） |

## 关键设计决策

### Middleware 城市路由

**文件**：`src/middleware.ts`

- 拦截所有请求，跳过静态资源
- 检查 `device_id` Cookie，不存在则生成 UUID
- 根路由 `/` 根据 `city_slug` Cookie 重定向到对应城市
- 确保用户始终看到自己选择的城市内容

### 全局状态管理

**文件**：`src/context/AppContext.tsx`

使用 React Context 管理：
- `favorites`：收藏列表（LocalStorage + Supabase 双写）
- `currentCity`：当前城市（Cookie + LocalStorage）
- `unreadNotifCount`：未读通知数
- `deviceId`：设备唯一标识

### 数据获取策略

**文件**：`src/utils/db.ts`

- 服务端：`getListings()` / `getListingById()` 支持 Supabase 查询
- 降级：查询失败时返回 `DEFAULT_LISTINGS` 默认数据
- 超时控制：5 秒超时避免阻塞渲染

## 性能优化

### 服务端渲染 (SSR)

- 城市列表页在服务端预取数据
- 避免首屏闪烁，提升 SEO
- 使用 `revalidatePath` 刷新缓存

### 客户端优化

- `useMemo` 缓存过滤结果
- `useCallback` 稳定函数引用
- 图片懒加载（浏览器原生）
- 路由预取（Next.js 自动）

### 缓存策略

| 数据类型 | 缓存位置 | 过期策略 |
|----------|----------|----------|
| 城市偏好 | Cookie + LocalStorage | 1 年 |
| 收藏列表 | LocalStorage + Supabase | 实时同步 |
| 设备 ID | HttpOnly Cookie | 1 年 |
| 商品数据 | Next.js 缓存 | 发布后刷新 |

## 安全设计

### 设备认证

- 使用 `device_id` Cookie 标识用户
- HttpOnly + Secure 标志防止 XSS
- 无需登录即可使用核心功能

### 数据验证

- Server Action 验证必填字段
- 类型安全（TypeScript）
- 输入过滤（XSS 防护）
